## What's new

### Personal memory
Personal memory now has categories, importance, expiry, edit, delete, search, duplicate detection and merge. Export is available as JSON or Markdown, and memories can be backed up to Drive.
- **Relevant memories only.** Prompts no longer include every memory. Only the few that relate to the question are used, and each answer shows "🧠 N memories used".
- **Suggest from current chat.** Abhify proposes candidate memories from the current chat, and you approve each one. Nothing is saved automatically.
- **Sensitive data check.** Anything that looks sensitive (email, phone, card, ID or PAN numbers, passwords, health or financial details) needs extra confirmation. A "remember that …" message containing such data is refused.

### Chat history
- Search uses SQLite full-text search where the phone supports it. Otherwise it falls back to plain text matching.
- Filter by date (from/to), archive and restore chats, and load more (50 per page).
- Send a conversation to Google Drive.

### Document library and RAG (retrieval-augmented generation)
- **Indexing.** Documents are split into chunks (with page numbers) and indexed on the phone. Documents imported before 3.4 are indexed in the background after start-up.
- **No duplicates.** A SHA-256 check stops the same file being imported twice.
- **Use in chat.** Pick documents with the 📚 chip or the "Use in chat" button. Answers then cite their sources as [S1], [S2] and so on.
- **Uncited answers.** If an answer cites no source, it is marked as general knowledge.

### Google Drive (optional)
- Uses the narrow `drive.file` scope and the official Google sign-in.
- Creates an `Abhify.AI/` folder tree, with each folder created only when first needed.
- Upload, download, list and move to trash (always with confirmation).
- **No silent overwrites.** Unchanged files are skipped. A changed file with the same name asks whether to replace it, keep both or cancel.
- **Interrupted uploads.** Uploads resume from where they stopped and retry on failure. Failed uploads stay in a local queue with a Retry button.
- See [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md). Drive needs a one-time Google Cloud OAuth client. Without it, Connect shows a clear "not configured" message.

### Unified chat and context controls
- **Default model.** New installs use the phone's Qwen model by default. Existing installs keep their setting.
- **No automatic switch to the cloud.** If the local model fails, an "Ask <provider> instead…" button appears. It works only after the usual consent dialog.
- **⚙ Online context.** Choose whether recent chat messages and relevant memories may go with an online request. Document passages always need a separate approval.

### Backup and restore
- **Backup.** Choose categories, add an optional passphrase (AES-256-GCM encryption), and save to a local file or to Drive.
- **Restore preview.** Before restoring, you see new versus already-present rows per table, and a damaged backup is refused.
- **Restore is additive only.** Existing rows are never changed or deleted, and restoring the same backup twice adds nothing.
- **Never in a backup:** API keys, OAuth tokens, passwords, signing keys or the model file.

### Storage
- A Storage screen shows the space used by the model, chats, memories, documents, the search index and the cache.
- "Clear cache" empties only the app's temporary cache folder. The model is never deleted automatically.

## Unchanged
- The Qwen2.5 model and its configuration.
- Text recognition (ML Kit), voice, Career Copilot 2.0, Study and Workspace.
- The desktop/web app and `cloud/`.
- Permissions: identical to 3.3.0. No new Android permissions.

## Added dependency
`com.google.android.gms:play-services-auth:21.3.0`, used for the Google sign-in prompt for Drive.

## Known limitations
See [V3_4_KNOWN_LIMITATIONS.md](V3_4_KNOWN_LIMITATIONS.md) and the limitation sections in each guide. In brief:
- Drive needs an OAuth client to be set up first. Real Drive sign-in has not been tested.
- Drive uploads run while the app is open; they don't use a background job.
- Memory "suggestions" use the local model, so their quality depends on it.
- The 3.4 build has not been tested on a physical phone yet.
