## 2. Plan (reuse first, additive only)

| Priority | Item | How |
|---|---|---|
| P0 | Safety | Database v9 is additive. Search indexes (FTS4) are created in a separate, idempotent, failure-tolerant step with a `LIKE` fallback. Regression suite kept. |
| P1 | Personal memory | `memories` gains category, importance, confirmed, source, expires_at. **Relevant-only retrieval** (top 6 by term overlap, category and importance) replaces "all memories". "Memories used" is shown per answer. User-approved extraction (AI proposes, the user ticks). Duplicate detection and merge. Sensitive-data warning. Export (JSON/MD) and Drive backup. |
| P2 | RAG | `library_docs` gains a content hash (duplicate import refused), source and indexed_at. Persistent `doc_chunks` plus FTS4 candidates, then BM25 ranking. Background indexing of existing documents. **Chat with selected documents** (several), with `[S#]` sources under each answer and consent before online use. |
| P3 | Google Drive | Official Android Authorization API (`play-services-auth`, scope `drive.file` only) and Drive REST v3 through our own small transport (mockable). Folder tree `Abhify.AI/…` created lazily, folder IDs cached and re-created if deleted. Uploads are resumable with retry. MD5 duplicate detection. Conflicts (same name, different content) are never overwritten silently. Download, list, delete (confirmed). Status table `drive_files`. **Real use requires Google Cloud Console configuration (documented).** |
| P4 | Unified chat | Local Qwen is the default for **new** installs (existing installs keep their mode). If local generation fails, the error is shown with "Retry" and "Ask <provider> instead" (explicit, behind the consent dialog). **No silent fallback.** Context controls for online requests: conversation, personal memory, selected documents. The routing (existing) is shown in the destination line. |
| P5 | Storage, backup, restore | Storage dashboard (database, archive, memory, documents, Drive downloads, model, cache; clear cache). Versioned backup (`abhify-backup` v1 JSON, per-category, SHA-256 integrity, optional passphrase AES-GCM). Local export and Drive upload. **Restore preview, then an additive restore** (skips existing uids, never overwrites). |
| P6 | Roadmap | `docs/FUTURE_ENHANCEMENTS.md` |

## 3. Security

- No secrets in code or the APK. The OAuth client is identified by package and SHA-1 (no secret). Access tokens are short-lived and kept in memory only.
- Backups never contain keys, tokens or signing material.
- Nothing is uploaded automatically: every Drive upload is a user action.
- Memory and documents go online only with consent.

## 4. Tests

JVM tests with mocked Drive HTTP, sqlite-jdbc migrations (including FTS4), memory retrieval, duplicates and sensitive data, backup codec, integrity, encryption and restore plan, RAG chunk store, chat context rules. Instrumented tests for backup and restore on a scratch database (built; device pending).

## 5. Risks

- **Drive:** cannot be tested without the owner's Google Cloud project, so it is marked pending.
- **FTS4:** availability on every device. Mitigated by the optional index with `LIKE` fallback.
- **Small local models:** they may extract memories poorly. Every candidate needs approval.
