# Offline operation (2.0.0-dev.6)

After automatic setup has finished (`AUTOMATIC_SETUP.md`), Abhify.AI's core features need **no network at all**. Startup downloads nothing, and normal use never installs anything.

## What works offline
| Feature | Offline | Notes |
|---|---|---|
| Start, settings, history, memories | ✅ | SQLite in your data folder |
| Chat with the local AI | ✅ | Ollama on this PC (GPU or CPU) |
| Your documents: upload, knowledge folder, search, citations | ✅ | Local embeddings + ChromaDB (telemetry switched off) |
| Interview questions, quizzes | ✅ | Generated by the local AI |
| Phone companion over your home network | ✅ | Tailscale needs its own connectivity |
| Private voice (Whisper) | ✅ **after** its first use online | See the limitation in `AUTOMATIC_SETUP.md` |
| News | ❌ | Shows saved news with its age |
| Web search in chat | ❌ | The answer says the computer is offline |
| Update checks | ❌ | Skipped silently; everything else continues |

## How this is verified (`backend/tests/test_offline.py`)
- The real app (FastAPI startup, SQLite, ChromaDB, the LangGraph agent) runs with **every non-local network connection and DNS lookup refused** at the socket level. Only Ollama is a stand-in, on `127.0.0.1`.
- Checked: startup, `/health` (`internet: false`), saving a memory, uploading and indexing a document, a chat that finds the document and cites it, the history list, and a **restart** with all data still there.
- Nothing tried to reach a model registry, package index, model hub, telemetry service or GitHub.

The physical-hardware run on the development PC (GPU, real Ollama models) is in `FINAL_ACCEPTANCE_DEV5.md` §3b. A full offline run on a real second PC is still to do (`PHYSICAL_PC_ACCEPTANCE_TEST.md`).

## If the internet drops while you work
Nothing is lost. A running chat continues (it's local); a web search inside it reports that the computer is offline. A model download in progress stops and resumes later. An update download stops; its partial file is kept.
